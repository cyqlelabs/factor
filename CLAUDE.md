## Conventions

Commit messages follow [Conventional Commits v1.0.0](https://www.conventionalcommits.org/en/v1.0.0/) (`feat:`, `fix:`, `docs:`, `test:`, `chore:`, …).

## Commands

```bash
make check                                  # full gate: vet + race tests + coverage ≥90% + gofmt check (what CI runs)
go test ./internal/agent -run TestName      # single test
make test-race                              # race detector (needs CGO_ENABLED=1; everything else is CGO-free)
make cover                                  # statement coverage, fails under 90%
make lint                                   # golangci-lint (.golangci.yml)
make build                                  # local binary
make build-tiny                             # -tags nobrowser strips the CDP browser suite (stubs in internal/browser/browser_stub.go)
```

The coverage gate is real: new code needs tests or `make check` fails. Live tests (real headless Chrome, real desktop round-trip) auto-skip in `-short` mode or when the machine can't host them; the rest of the suite runs against fakes — scripted providers, a fake smrti sidecar (spawned by re-execing the test binary), a fake Telegram API, a fake MCP server over real stdio JSON-RPC, and a scripted desktop backend.

Grid vision is covered end to end at two levels, both of which locate the target and read the grid **out of the rendered pixels** rather than from the grid code, so an overlay or translation that is wrong cannot agree with the test:

- `internal/desktop/grid_live_test.go` — a private Xvfb with solid-color blocks at known screen positions; the real helpers capture and the real `xdotool` moves the pointer, which must land inside the block. Covers coarse pointing, a small target only the zoom pass can hit, region zoom, a downscaled frame on a big screen, and re-grounding after the screen changes. Needs Xvfb, scrot, xdotool and xlogo (CI installs them; missing helpers skip).
- `internal/agent/vision_loop_e2e_test.go` — the whole turn with no display: real loop, registry, desktop tools and provider over a local HTTP server, with a fake vision model that decodes the PNG that actually crossed the wire, names a cell, and clicks it. Runs everywhere, so the CI boxes where the live tests skip still cover the path.

## Architecture

Factor is a single static Go binary (`cmd/factor`): a desktop AI agent with long-term memory, reachable over CLI or Telegram. `internal/app` is the composition root — it wires everything below into one `App` shared by the CLI modes and the `factor gateway` daemon (`internal/gateway`, which adds PID-file management, cron, and heartbeat). `factor gateway -d` re-spawns the gateway detached (own session on unix, no console on Windows), confirms startup through the pid file the child claims, and leaves its output in `~/.factor/gateway.log`. While the gateway runs in a desktop session, `internal/tray` shows a systray icon whose quit item stops it cleanly (`gateway.RequestStop`); the tray is pure Go on Linux (StatusNotifierItem over the session D-Bus — no bus, no icon, nothing else changes) and Windows, and stubbed elsewhere because a macOS tray needs cgo the CGO-free builds cannot carry. The tray owns the main goroutine; the gateway serves from a goroutine beside it.

Message flow:

```
channels → bus → agent loop → provider chain
                     └→ tool registry ─ every tool suite
memory recall injects into each turn's context; turns are stored back after
jobs / cron / heartbeat publish results onto the bus, re-entering sessions proactively
```

- **`internal/bus`** — bounded queues decoupling connectors from the loop. Publishing never blocks; a full queue drops loudly. `OutboundMessage.Interim` marks a note sent while its turn is still running, so a channel can treat it differently from the reply that follows. `bus.External` is the one rule for whether a channel is somewhere Factor can reach the user unprompted — the CLI, `system` and `cron` are not — and every proactive sender (heartbeat, cron results, release and restart notices) addresses the last external chat, which `internal/agent` keeps in `~/.factor/last-channel.json` so a fresh process is not mute until the user speaks first. That address only counts while a connector is running for it: the gateway hands the loop `Manager.Serves` (`Loop.SetReachable`), so a chat whose channel is switched off is withheld rather than reported as delivered and then dropped by the pump.
- **`internal/channel`** — connectors self-register via `channel.Register(name, factory)` in package `init()`, keyed to their own raw-JSON config section. Telegram is the model implementation. Two optional capabilities exist for connectors that need them: `Typer` (typing indicator) and, for synchronous conversations, `TurnRunner` + `Toolset`, wired by the gateway.
- **`internal/channel/phone`** — voice: real phone calls and SMS. Turns bypass the bus — a localhost OpenAI-compatible bridge (`/v1/chat/completions`, SSE) drives `Loop.ProcessDirectNotice` under `phone:<E.164>`, so hanging up cancels the turn. What the agent says on its way to an answer is streamed into the live call as an early content delta, ahead of the reply; off the line an interim is dropped, being worth neither a text nor a second call. A supervised Python sidecar (Patter, `voiceshell.py`, embedded via `go:embed`) owns the carrier and the speech pipeline; the speech tier is cloud or local per config, with a startup probe that falls back to cloud when a local server is down. The carrier is Twilio or Telnyx (`carrier` in the config): each has its own credentials, its own wire format for synthesized audio, and its own hangup call, and on Telnyx the shell also attaches the number to the Call Control Application and points its webhook at itself on every start (Patter only auto-configures Twilio). SMS goes straight to the carrier's REST API from Go (`carrier.go`).
- **`internal/channel/voice`** — PC voice: the machine's own mic and speakers. Audio rides helper programs (`parec`/`paplay` preference chains, no cgo) through the `Env` seam; VAD, wake-word gating, and barge-in are pure Go. Each utterance runs synchronously through the bound `TurnRunner` under `voice:local`, so an accepted barge-in cancels the in-flight turn and discards playback, while a rejected one (wake-word mode) resumes the reply where it paused. A note the turn makes on its way to the answer is spoken as it happens, queued against the answer behind it, so a minute of tool calls does not sound like a hang. The speech tiers are the phone's — same cloud providers spoken from Go, or the managed local server via `phone.SpeechServer` on its own port (8728) — with the same probe-and-fall-back at startup. A loopback control endpoint (8730) takes `factor talk` push-to-talk, which also overrides a misfired wake word; `voice_write` (via the `Addresser` capability) delivers written replies to the terminal or the last external chat. The CLI builds this one channel itself in `runChat`, so the mic works without the gateway, and feeds the TUI bar a live meter (`Voice.Meter`: level, floor, digital-silence flag, speaking). The wizard picks the capture device from `pactl`'s source list and verifies it live (`MeasureMic`) — a source delivering exact zero is the wrong-device signature, also surfaced at runtime on the control endpoint's `/health` and as a log warning.
- **`internal/agent`** — the loop enforces **one live turn per session key** (`channel:chatID`). A second message arriving mid-turn becomes *steering*: injected between tool iterations under the same lock that guards turn release, and leftovers are republished as fresh inbound. Text the model emits alongside its tool calls is the agent saying what it is about to do: it goes out as `PhaseNotice` while the tools run rather than at the end of the turn. A bus-driven channel gets it from `Manager.Interim`; a connector that runs its own turns (voice, phone) gets it straight from the turn instead, through the `notice` callback `ProcessDirectNotice` threads into `channel.TurnFunc` — the one place the line arrives while it is still true, and the reason a spoken turn spent in tools is audible progress rather than dead air. `compact.go` handles context-overflow compaction at turn-safe boundaries. `context.go` (ContextBuilder) assembles system prompt + skills catalog + memory recall. A tool result carrying images (`tools.Result.Images`, e.g. `screen_view`'s annotated screenshot) rides a follow-up user message — the one placement every vision dialect accepts — with only the newest 2 frames kept in the in-flight context and only a text placeholder persisted to session history.
- **`internal/provider`** — a failover `Chain` of candidates. `openai.go` speaks every OpenAI-compatible dialect (OpenRouter, Ollama, Groq, …); `anthropic.go` is native. `classify.go` decides retry vs. failover vs. compaction; `reasoning.go` translates one reasoning config into each provider's dialect. `Message.Images` attaches images to user messages, translated per dialect (content-parts with data URIs vs. base64 source blocks); plain messages keep bare-string content.
- **`internal/memory`** — smrti (Python) runs as a supervised REST sidecar: spawned, health-checked, restarted with backoff, auto-installed when missing (`install.go`). `Ambient` does per-turn recall→inject and store; everything degrades gracefully (empty recalls, dropped writes) when the sidecar is down. Memory is also exposed as deliberate tools (`remember`/`recall`/`forget`/`reflect`).
- **`internal/tools`** — the registry. A tool implements `Name/Description/Parameters/Execute` and registers once; users disable via `tools.disabled` config. `guard.go` (PathGuard) enforces workspace restriction with symlink resolution; exec has deny-patterns; secrets are scrubbed from every tool result at the registry layer. Other suites register into the same registry: `internal/browser` (CDP; two engines — the Chromium suite, plus an opt-in renderer-less Lightpanda fast path in `fast.go` that adds `browser_fetch` and only reads pages — over an engine `install.go` provisions itself, downloading Helium when the machine has no browser), `internal/desktop` (X11/Wayland/macOS/Windows via helper commands; `MachineHasDisplay` probes the machine's display server rather than `$DISPLAY`, so setup over ssh targets the desktop the box is running; `grid.go`+`vision.go` add grid vision — `screen_view` overlays a battleship coordinate grid on the captured screen, `screen_zoom` magnifies a cell under a finer sub-grid, and `mouse cell=D4` resolves either grid back to native pixels, all pure Go image math with frames capped at 1568px), `internal/jobs` (background jobs whose completions re-enter the session), `internal/cron`, `internal/mcp` (mounts external MCP servers' tools at runtime), `internal/skills` (markdown skills, catalog-in-prompt with full text on demand).
- **`internal/config`** — `~/.factor/config.json`, every key optional, `FACTOR_*` env overrides declared as struct tags. The agent's home is `~/.factor/workspace` (`AGENT.md`, `SOUL.md`, `USER.md`, `HEARTBEAT.md`, `instructions/`, `skills/`, `sessions/`, `cron/`).
- **`internal/tui`** — the interactive chat console (used by `cmd/factor`): owns the bottom rows of the terminal — a live activity line plus a prompt that stays editable while a turn runs — with replies landing above; falls back to plain lines without a TTY (pipes, `TERM=dumb`).
- **`internal/upgrade`** — self-update. Finds the newest GitHub release for this GOOS/GOARCH, verifies the download against the release's `SHA256SUMS`, and swaps the running binary (stage beside it, two renames, roll back on failure). Installing is not enough on its own — a running process keeps the code it loaded — so the gateway reloads: it waits for the turn in flight to be answered and its reply to drain off the outbound queue, shuts down cleanly, then execs the new binary at the path it was started from (same pid, so systemd never sees it stop). The reload is requested by the `upgrade` tool mid-conversation or by SIGHUP, which is how `factor upgrade` in a terminal reaches the daemon it just replaced. An exec keeps the pid and nothing else, so the outgoing process leaves a note in `~/.factor/restart-notice.json` naming the chat that asked (or, for a SIGHUP, the last one used); the process that comes up delivers it, deletes it, and ignores one older than 15 minutes — that is the "I'm back" line after an upgrade. The gateway still only *reports* a new version it finds on its own — once per version, into the last active chat; installing is always asked for. smrti is kept current by the same mechanism (`smrti.go`), but it ships as a container image, so there its upgrade is a registry lookup and a container swap: the engine is found by the port it publishes (the container answering `memory.port` is by definition the one Factor talks to), the published image is pulled first, and the container is then recreated from its own spec — same volumes, same `-e` settings, same ports, with everything its old image supplied left to the new one — so the graph on disk and the way it was configured both survive. The swap waits for a quiet graph (`memory.IdleFunc`: nothing in flight and nothing finished in the last 15 seconds, health probes not counting) and rolls back to the container it replaced if the new one does not answer, so the engine is replaced under a live Factor with no restart of its own. A `factor upgrade` in a terminal cannot see what the daemon has in flight, so it asks over the gateway's health endpoint (`memory_idle`).
- **`internal/wizard`** — the `factor init` interactive terminal wizard. Every step is verified live (provider completion, model list from the endpoint, Telegram `getMe`, carrier and voice credentials, a real page load through the browser), and the wizard provisions what is missing rather than reporting it: smrti, a browser, the desktop helpers the backend wants. Live engines are probed before an install is offered, so a smrti or voice shell running elsewhere is never offered a local install on top of it. The autostart step follows the same rule: saying yes installs the login entry itself (`internal/autostart` — a systemd user service where a user manager answers, an XDG autostart entry otherwise, a launchd agent on macOS, the Windows Run key), declining while one exists removes it, and the default mirrors what is already in place so Enter never changes how the machine boots.

Design intent: guardrails (PathGuard, deny-patterns, allowlists, redaction) protect against accidents and casual prompt injection — they are explicitly **not** a security boundary. Factor is a single-user personal agent.
